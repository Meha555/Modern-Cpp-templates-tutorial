# 待决名

### 定义

> [文档](https://zh.cppreference.com/w/cpp/language/dependent_name)

如果一个名字（变量、函数、类型等）的解析依赖于模板参数，则称为**待决名/依赖名/从属名（*Dependent Name*)**。反之则是**非待决名/非依赖名/非从属名/独立名（*Non-dependent Name/Independent Name*）**。

**编译器在一阶段（模板定义阶段）只查找非待决名而不会查找待决名，而是在二阶段（模板实例化阶段）再查找**。

*注：本文会混用待决名和依赖名、非待决名和独立名、非依赖名等称谓，不必在意。*

**待决名和SFINAE关系紧密，两者需要结合起来理解。**

**判断口诀：**只要名字的类型或值依赖于模板参数，就是依赖名，否则就是非依赖名。

- 不过要注意，对一个类似 `T obj/T func()` 的定义/声明讨论其是不是依赖名是没有意义的，因为它根本不涉及名字查找，它是在用一个 `T` 创造一个名字；而对于一个类似 `T::type obj/T::type func()` 的定义/声明讨论其是不是依赖名是有意义的，因为它虽然是在创造一个名字，但用的是 `T::type` 这个依赖名。

注：==着重看**两阶段名字查找**，其他内容都是在对这个两阶段名字查找换个说法继续解释。==

#### 非依赖名

##### 非模板类型

```cpp
int a = 10;
void f();
```

##### 模板定义中不依赖模板参数的名字

```cpp
template <typename T>
class Example {
    int count;  // 非依赖名（尽管在模板类中，但类型int不依赖T）
    void foo() // 非依赖成员函数（尽管在模板类中，尽管函数体使用了依赖名val，但不依赖T，因为名字查找不关心函数体，在使用foo时能直接看到Example的定义中有foo）
    {
        val++;
    }
    T val;
};
```

##### 模板定义中当前实例化的成员

```cpp
template <typename T>
struct X {
    T a;
};
int main() {
    X<int> x; // struct X<int>是当期实例化的成员，是非依赖名
              // 而x.a则不是，它只是依赖于T类型，是依赖名
}
```

#### 依赖名

##### 直接带有模板参数

就是直接带有模板参数的名字。

```cpp
template<typename T, size_t N>
void foo() {
    T obj;           // T 是依赖名
    T* ptr;          // T* 是依赖名
    std::vector<T> v; // std::vector<T> 是依赖名
    int array[N];     // array 是依赖名
}
```

##### 嵌套依赖名(Nested-dependent Name)

```cpp
template <typename T>
void foo() {
    typename T::iterator iter;  // T::iterator 是嵌套依赖名
    T::template Func<int>();    // T::Func 是嵌套依赖名
}
```

##### 模板定义中非当前实例化成员

```cpp
// (1)
template<typename T>
struct Derived : T { // T 是依赖基类，Derived定义的时候T还没有实例化
    void demo() {
        this->member;  // this->member 是依赖名
    }
};
// (2)
template<typename T>
class Example {
    std::vector<T> data; // 依赖名，当前实例化的是Example
};
```

对于(1)，编译器在二阶段才在实例化后的T中查找是否存在 `T::member` ；对于(2)，编译器在二阶段才检查实例化后的T是否符合 `std::vector` 的要求。

因此，只有在使用了依赖名后，编译器才能发现潜在的错误，如果用都没用，那么就只停留在阶段一，相当于实际上没有完成完整的依赖名查找。

#### 示例

```cpp
template <typename T>
class MyContainer {
public:
    void non_dependent() {
        std::cout << "Non-dependent: " << var << std::endl;
    }
    void dependent(T val) {
        T local = val; // 依赖名：T
        std::cout << "Dependent: " << local << std::endl; // 这里会编译错误，编译器无法确定T是否支持operator<<(std::ostream&)操作符
    }
    // 嵌套依赖名
    typedef typename T::value_type value_type; // T::value_type是依赖名，需要typename
    // 另一个例子：依赖作用域中的函数模板
    template <typename U>
    void templated_member(U u) {
        // 调用一个依赖名（成员函数模板）需要template关键字
        val.template some_templated_func<U>(u);
    }
private:
    T val; // 依赖名
    int var = 42; // 非依赖名
};
int main() {
    MyContainer<std::vector<int>> container; // 因此T类型是std::vector<int>，这是在阶段一就
    container.non_dependent(); // OK
    // 如果我把下面这句注释掉，则上面dependent函数就不会报错了！就是因为没有实例化dependent方法，导致没有进行第二阶段的名字查找
    container.dependent(10); // Error：这里T是std::vector<int>，但dependent函数中T作为整数类型使用，
    return 0;
}
```

## 使用 `typename` 指明依赖名是一个类型

**在模板（包括别名模版）的声明或定义中，不是 当前实例化的成员 且 取决于某个模板形参 的名字不会被认为是类型，除非使用关键词 `typename` 或它已经被设立为类型名（例如用 `typedef` 声明或通过用作基类名）【因为这样没有歧义】**。

总之，当依赖名应当表示类型但又存在歧义时，必须用 `typename` 消除歧义。

```cpp
template<typename T>
void foo() {
    typename T::Inner x; // 声明 T::Inner 是类型
}
```

关键词 typename 只能以这种方式用于限定名（例如 T::x）之前，但这些名字**不必待决**。

以下 `v` 不是待决名（因为 `std::vector<int>` 不是模板），但是的确可以以 `typename` 修饰，虽然没啥用处。

```cpp
typename std::vector<int>::value_type v;
```

### 示例

#### 示例1

```cpp
template <typename T>
const /*typename*/ T::type& f(const T&) {
    return 0;
}

struct X {
    using type = int;
};

int main(){
    X x;
    f(x);
}
```

报错：

```cpp
MSVC:
error C2061: 语法错误: 标识符“type”
error C2143: 语法错误: 缺少“;”(在“{”的前面)
error C2447: “{”: 缺少函数标题(是否是老式的形式表?)
error C2065: “x”: 未声明的标识符
error C3861: “f”: 找不到标识符

GCC:
<source>:2:7: error: need 'typename' before 'T::type' because 'T' is a dependent scope
    2 | const T::type& f(const T&) {
      |       ^
      |       typename 
<source>: In function 'int main()':
<source>:12:5: error: 'f' was not declared in this scope
   12 |     f(x);
      |     ^        
```

总的意思也很简单，**编译器不觉得你这个 `type` 是一个类型**。

我们只需要在 `T::type&` 前面加上 `typename` 就能够通过编译。那么为什么编译器不觉得你这个 `type` 是一个类型呢？逐步分析：

> 在模板（包括别名模版）的声明或定义中

我们函数模板 `f` 自然是在模板中，符合。

> 不是当前实例化的成员且取决于某个模板形参的名字

<u>`T::type` 的确不是当前实例化的成员，当前实例化的是函数模板 `f`；`T::type` 是依赖于 `T` 类型而非实例化</u>，简单的说就是 `T::type` 是什么，取决于当前的函数模板。符合。

> 不会被认为是类型

是的，所以我们前面没有使用 `typename` 产生了编译错误。

> 除非使用关键词 typename 或它已经被设立为类型名（例如用 typedef 声明或通过用作基类名）

是的，我们后面的示例使用了 `typename` 就没有问题了，`T::type` 被认为是类型了。

#### 示例2

```cpp
int p = 1;

template <typename T>
void foo(const std::vector<T>& v){
    // std::vector<T>::const_iterator 是待决名，
    typename std::vector<T>::const_iterator it = v.begin();

    // 下列内容因为没有 'typename' 而会被解析成
    // 类型待决的成员变量 'const_iterator' 和变量 'p' 的乘法。
    std::vector<T>::const_iterator* p; // Error: Missing 'typename' prior to dependent type name 'std::vector<int>::const_iterator'

    typedef typename std::vector<T>::const_iterator iter_t;
    iter_t* p2; // iter_t 是待决名，但已知它是类型名
}

int main(){
    std::vector<int> v;
    foo(v); // foo实例化失败
}
```

这个就不逐句解释了，就说一下最后一句注释：

`iter_t` 是待决名，但已知它是类型名

> 除非使用关键词 typename 或它**已经被设立为类型名**（例如用 typedef 声明或通过用作基类名）

值得一提的是，只有在添加 `foo(v)`，即进行模板实例化后 gcc/clang 才会拒绝该程序；
如果你测试过 msvc 的话，会注意到，`typedef typename std::vector<T>::const_iterator iter_t;` 这一句，即使不加 `typename` 一样可以通过编译；

msvc 搞特殊，我们知道就行；不要只测 msvc，不然代码不可跨平台。

## 使用 `template` 指明依赖名是一个模板

**与此相似，模板定义中不是 当前实例化的成员 的待决名 同样不被认为是模板名，除非使用 `template` 消除歧义，或它已被设立为模板名：**

总之，当依赖名应当表示模板但又存在歧义时，调用时需加 `template` 。

```cpp
template<typename T>
void bar() {
    T::template Func<int>(); // 声明 T::Func 是模板
}
```

**关键字 `template` 只能以这种方式用于运算符 `::`（作用域解析）、`->`（通过指针的成员访问）和 `.`（成员访问）之后**，下列表达式都是合法示例：

- `T::template foo<X>();`
- `s.template foo<X>();`
- `this->template foo<X>();`
- `typename T::template iterator<int>::value_type v;`

与 `typename` 的情况一样，即使名字并非待决或它的使用并未在模板的作用域中出现，也允许使用 `template` 前缀。

```cpp
struct X{
    template<typename T>
    void f()const {}
};
struct C{
    using Ctype = int;
};

X x;
x.template f<void>();
C::template Ctype I;
```

*没有作用，但是合法*。

重复强调一下：**`template` 的使用比 `typename` 少，并且 `template` 只能用于 `::`、`->`、`.` 三个运算符 *之后*。**

### 示例

#### 示例1

```cpp
template<typename T>
struct S{
    template<typename U>
    void foo() {}
};
 
template<typename T>
void bar(){
    S<T> s;
    s.foo<T>();          // 错误：< 被解析为小于运算符
    s.template foo<T>(); // OK
}

int main() {
    bar<int>();
    
    S<double> s;
    s.foo<float>();     // 正确，不是待决名，无歧义
}
```

使用 `template` 消除歧义更加少见一点，一般鉴于上面这种从属名的语境。不过我们一句一句分析就行。

> 模板定义中不是当前实例化的成员的待决名同样不被认为是模板名

<u>`s.foo<T>()` 的确是在模板定义，并且不是当前实例化的成员，当前实例化的是 `bar` 。它只是依赖了当前的模板实参 `T` 而非实例化</u>，所以不被认为是模板名。

> 除非使用消歧义关键词 template

`s.template foo<T>()` 的确。

注意：`s.foo<T>()` 在 msvc 可以被解析，通过编译，这是非标准的，知道即可。

## 名字查找

> [为什么C++模板类的非限定名、待决名名字查找不考虑待决基类？ - 知乎 (zhihu.com)](https://www.zhihu.com/question/511729926)

[名字查找](https://zh.cppreference.com/w/cpp/language/lookup)很复杂，这里只讨论与待决名相关的部分内容。

名字查找分为：

- [**有限定**名字查找（*Qualified Lookup*）](https://zh.cppreference.com/w/cpp/language/qualified_lookup)：出现在作用域解析操作符 `::` 右边的名字是限定名。限定名可能代表的是：
  - 类的成员（包括静态和非静态函数、类型和模板等）
  - 命名空间的成员（包括其他的命名空间）
  - 枚举项
- [**无限定**名字查找（*Unqualified Lookup*）](https://zh.cppreference.com/w/cpp/language/unqualified_lookup)：不是出现在作用域解析操作符 `::` 右边的名字是非限定名。

```cpp
#include<iostream>

template<class T>
struct X {
    void f() const { std::cout << "X\n"; }
};

void f() { std::cout << "全局\n"; }

template<class T>
struct Y : X<T> {
    void t() const {
        this->f(); // 待决名（因为this实际上是Y<T>*，而Y<T>是待决名，因此this->f也是待决名），二阶段名字查找能找到父类的f
    }
    void t2()const {
        f();	   // 非待决名，一阶段名字查找能找到全局f（如果注释掉第8行，则报错there are no arguments to 'f' that depend on a template parameter, so a declaration of 'f' must be available，因为一阶段名字查找失败了）
    }
};

int main() {
    Y<void>y;
    y.t();
    y.t2();
}
/*输出
X
全局
*/
```

如果 `::` 左边为空，那么查找过程只会考虑全局命名空间作用域中作出（或通过 using 声明引入到全局命名空间中）的声明。

```cpp
this->f();
```

我们找到[官方文档](https://cppreference.cn/w/cpp/language/unqualified_lookup)中的**模板定义**小节：

> 对于在模板的定义中所使用的**非待决名**，当**检查该模板的定义时将进行无限定的名字查找**。在这个位置与声明之间的绑定并不会受到在实例化点可见的声明的影响。而对于在模板定义中所使用的**待决名**，**它的查找会推迟到得知它的模板实参之时**。此时，ADL 将同时在模板的定义语境和在模板的实例化语境中检查可见的具有外部连接的 (C++11 前)函数声明，而非 ADL 的查找只会检查在模板的定义语境中可见的具有外部连接的 (C++11 前)函数声明。（换句话说，在模板定义之后添加新的函数声明，除非通过 ADL 否则仍是不可见的。）如果在 ADL 查找所检查的命名空间中，在某个别的翻译单元中声明了一个具有外部连接的更好的匹配声明，或者如果当同样检查这些翻译单元时其查找会导致歧义，那么行为未定义。无论哪种情况，**如果某个基类取决于某个模板形参，那么无限定名字查找不会检查它的作用域（在定义点和实例化点都不会）**。

很长，但是看我们加粗的就够：

- 非待决名：检查该模板的定义时将进行无限定的名字查找
- 待决名：它的查找会推迟到得知它的模板实参之时

我们这里简单描述一下：

`this->f()` 是一个待决名，这个 `this` 依赖于模板 `X`。

所以，我们的问题可以解决了吗？

1. `this->f()` **是待决名**，所以它的查找会推迟到得知它模板实参之时（即模板实例化时，届时可以确定父类是否有 f 函数）。
2. `f()` **是非待决名**，检查该模板的定义时将进行无限定的名字查找（无法查找父类的定义），按照正常的查看顺序，先类内（查找不到，因为父类还没实例化），然后全局（找到）。

>补充：如果是 `msvc` 的某些早期版本，或者 C++ 版本设置在 C++20 之前，会打印 `X` `X`。这是因为 `msvc` 不支持**二阶段名字查找** [`Two-phase name lookup`](https://learn.microsoft.com/zh-cn/archive/blogs/c/msvc%E5%B7%B2%E7%BB%8F%E6%94%AF%E6%8C%81two-phase-name-lookup)。

### 两阶段名字查找（Two-phase name lookup）

> C++20 强制两阶段名字查找。

#### 概念

模板会进行两次名字查找：

1. 在模板定义阶段，编译器会检查模板的语法，查找模板中的**非依赖名**【所有模板都会进行的，是**非限定名字查找**】
   - 目的：确保没有基本的语法错误（语法分析）

2. 在模板实例化阶段，查找模板中的**依赖名**【只有用到了而被实例化的模板才会进行，是**有限定名字查找**】
   - 目的：确保所有调用都对该特定类型有效，例如：模板可能会反过来调用该特定类型可能不存在的函数（语义分析）

> Also note that lookup for non-dependent names is done in the first phase, whereas lookup for names that depend on a template parameter is done in the second phase. The significance is that if you call `sqrt(1)`, then `sqrt` needs to be declared before the template is defined. But if you call `sqrt(t)`, where `t` is an instance of a type that's a template parameter, then `sqrt` needn't be visible until the template is instantiated.
>
> In addition, it's also worth pointing out that it's "argument dependent lookup" that happens on the dependent names. This means that `::sqrt(::NS::A)` will not be found as the additional lookup will take place in `::NS` and not in `::`. The final point is that the scope of an alias, typedef or using, won't be searched, only the scope of the alised type itself.

#### 示例

##### 示例1

在看华为aki框架时发现的一个场景，抽象一下：

```cpp
template<typename T>
void bar(T *p) {
    p->f(); // OK: T是依赖名，且由于没有用到bar这个函数模板，因此bar没有实例化，所以不会发生二阶段，因此即使T类型没有成员函数f也不会报错（因为根本不知道T类型是谁）
}

void foo() {
    int *p = new int;
    p->f(); // 错误：int是非依赖名，且没有成员函数f
}

int main() {
    int p;
    bar(&p); // 如果有这句话，则编译失败。
             // 因为编译器尝试实例化bar<int>，于是在二阶段发现int没有成员函数f，报错
}
```

##### 示例2

一个典型的待决名场景：

```cpp
template<typename T>
class A {
public:    
    void f() { std::cout << "A::f()" << std::endl;  }
};

template<typename T>
class B: public A<T> {
public:   
    void g() { 
        f(); // error: there are no arguments to 'f' that depend on a template parameter, so a declaration of 'f' must be available [-Wtemplate-body]
    }
    // void f() {} 加上这句就编译通过了(或者放到类外也行)
};
// 
```

上例中的 `f` 由于不是 `B` 的直接成员，也不依赖任何模板参数（所以编译器认为其是非依赖名），因此编译器在阶段一就认为 `f` 是非 `B` 的成员函数，而基类 `A<T>` 由于依赖模板参数（所以是依赖名）而推迟到阶段二 `A<T>` 实例化时才查找 `A<T>::f` ，导致编译器又去全局命名空间查找 `f` ，结果也没有，所以找不到报错。

*注：这段代码在G++下无法通过，但在MSVC下可以通过，是MSVC的拓展（MSVC不支持二阶段名字查找，他们做的实际上是一阶段名字查找，只是这个一阶段也做了二阶段的事情，所以这里能通过），允许在当前类B的基类A是dependent名字的情况下查找A的成员（这个本来是在二阶段才能做到），因此发现有 `A<T>::f` 。*

改正方法：

- 思路1（阶段一名字查找）：给 `B` 加上成员函数 `f` 或者实现一个全局函数 `f` ，即提供一个名字，`f` 仍然是非依赖名。
- 思路2（阶段二名字查找）：把 `f()` 改成 `this->f()` 或 `B<T>::f()/A<T>::f()` 来显式让 `f` 成为依赖名，则编译器对 `f` 的查找会推迟到阶段二，从而 `A<T>` 已经实例化，可以找到 `A<T>::f` 。

> Q：为什么要两阶段名字查找？像MSVC那样只在实例化阶段查找不行吗？[Two phase name lookup for C++ templates - Why? - Stack Overflow](https://stackoverflow.com/questions/12561544/two-phase-name-lookup-for-c-templates-why)

> A：先不关心语法检查，关键在与名字查找。如果非依赖名和依赖名的名字查找都放在阶段二即实例化的时候，那么就造成当前翻译单元（.cpp和所有级联include进来的内容）内会混杂着普通类型和实例化的模板类型，导致可能出现本来是非依赖名凑巧选择了一个名字一样的依赖名，或者反之（称为劫持）。再加上在适当情况下为依赖名指定 `typename` 和 `template` 的语法要求，从而还实现了在模板定义时就能进行解析和一些错误检查，而不仅仅是在模板实例化时。

### 名字绑定

**非待决名在模板定义点查找并绑定。即使在模板实例化点有更好的匹配，也保持此绑定。【其实就是说非待决名只在一阶段进行名字查找】**

```cpp
// void g(int);
void g(double) { std::cout << "g(double)\n"; }

template<class T>
struct S{
    void f() const{
        g(1); // "g" 是非待决名，一阶段完成查找，在模板定义点即第4行查找匹配的名字g，发现能看到的只有g(double)（C++在函数定义的上方是无法使用这个函数的，除非前向声明）。如果我去掉第1行的注释，则这里就查找到了g(int)
    }
};

void g(float) { std::cout << "g(float)\n"; }
void g(int) { std::cout << "g(int)\n"; }

int main(){
    g(1);  // "g" 是非待决名，一阶段完成查找，查找到了g(int)

    S<int> s;
    s.f(); // "S<T>::f" 是待决名，虽然是二阶段完成查找，但由于第7行解释的原因，查找到 g(double)
}
/*输出：
g(int)
g(double) # MSVC输出g(int)，原因还是MSVC不支持二阶段查找
*/
```

`s.f()` 中调用的是 `g(1);` 按照一般直觉会选择到 `void g(int)`，但是实际却不是如此，它调用了 `g(double)`。
